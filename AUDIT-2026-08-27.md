# Carbon & Place audit — pipeline vs. website

**Date:** 2026-08-27
**Scope:** `build` (the R/`targets` pipeline) and `PlaceBasedCarbonCalculator.github.io` (the website), cross-checked against the sibling repos (`EPC`, `PublicTransportAnalysis`, `GBsolar`, `LandOwnership`) and against the built outputs in `build/outputdata/`.
**Purpose:** find places where what the pipeline computes and what the website says it computes disagree — mislabelled charts, methods documentation that does not describe the actual method, and internal inconsistencies that leak into the published numbers.

No code has been changed. Findings are ordered by severity. Every claim below is backed by a file reference and, where numbers are involved, by a value read out of the current `outputdata/`.

Legend for severity:

- **A — Wrong numbers reach users.** The site shows a figure that is internally inconsistent or on a different basis from the figure next to it.
- **B — Right numbers, wrong words.** The value is defensible but the label, legend, axis, or manual text describes something else.
- **C — Method issues.** Defensible-but-undocumented modelling choices, or genuine calculation errors that bias a component.
- **D — Housekeeping.** Stale text, dead config, placeholders.

## A. Wrong numbers reach users

### A3. Suppressed DESNZ gas/electricity is converted to zero, not to missing

**Where:** [R/lsoa_gas_electricity.R:37-40](R/lsoa_gas_electricity.R#L37) and [R/lsoa_gas_electricity.R:139-142](R/lsoa_gas_electricity.R#L139)

```r
gas$total_gas_kwh[is.na(gas$total_gas_kwh)] = 0
gas$mean_gas_kwh[is.na(gas$mean_gas_kwh)]   = 0
```

DESNZ suppresses small-count LSOAs. After `as.numeric()` those cells are `NA`; they are then set to `0`. Downstream, `dom_gas_total_emissions = total_gas_kwh * gas_kgco2e` gives exactly zero, which propagates into `total_kgco2e_percap` and into the Gas grade.

A neighbourhood whose gas data was suppressed is therefore indistinguishable on the map from one that is genuinely off the gas grid, and it receives an artificially good total-emissions grade. The manual ([manual/index.md:487](../PlaceBasedCarbonCalculator.github.io/manual/index.md#L487)) says only that "data for small areas is sometimes suppressed for privacy" — it does not say suppression is treated as zero consumption.

**Fix:** keep suppressed values as `NA` and let `value2grade()` return `"NA"`, or add a warning code for suppressed energy data; at minimum say so in the manual.

### A4. Missing synthetic-population years are silently zeroed

**Where:** [R/synth_pop_emissions.R](R/synth_pop_emissions.R), the loop after the `left_join(population, consumption_syth_emiss)`

```r
# NAs form LSOAs with 0 population
for(i in 1:ncol(consumption_syth_emiss)){
  if(inherits(consumption_syth_emiss[[i]],"numeric")){
    consumption_syth_emiss[[i]][is.na(consumption_syth_emiss[[i]])] = 0
  }
}
```

The comment says the NAs come from zero-population LSOAs, but the loop blanket-zeroes **every** numeric NA in the table, including any zone-year genuinely absent from the synthetic population. Those zones then show £0 spend and 0 kgCO₂e for every consumption category, sum into an artificially low total, and are graded on it.

**Fix:** restrict the coercion to the zero-population rows it is documented for, and let anything else stay `NA`.

## B. Right numbers, wrong words


### B2. The accessibility scatter plots two sentinel values as if they were real scores

**Where:** [R/access_proximity_funcs.R:100-122](R/access_proximity_funcs.R#L100)

```r
lim_pos = 3; lim_neg = -2.9
...
ap[,i] = if_else(is.na(ap[,i]) & (ap[,paste0("pop_",i)] / ap$nat_pps < 0.5), -3, ap[,i])
ap[,i] = if_else(is.na(ap[,i]), -2.9, ap[,i])
```

`-3` means "too few people in the catchment for this service to be expected" and `-2.9` means "missing / no services of this type". The **summary table** handles this correctly (`transport/ui.js`, `if (value == -3) … textContent = 'Insf'`). The **summary chart** does not: both sentinels are plotted as ordinary points pinned at the bottom-left corner of a chart whose axes run `-3 … 3`. Every neighbourhood's scatter therefore has a false cluster of "worst in Britain" points.

Also, `-2.9` is used for "no services at all", which is a real observation, not a missing value — see also B3.

**Fix:** drop sentinel values from the scatter (or draw them in a distinct "not applicable" band outside the axis range), and mention both sentinels in the manual's accessibility method section, which currently says only that values are "truncated to the -3 to +3 range".

## C. Method issues

### C1. Van and motorbike/company emissions use the car fleet's gCO₂/km

**Where:** [R/car_emissions.R:255-259](R/car_emissions.R#L255)

```r
lsoa$car_emissions          = lsoa$car_km     * lsoa$AvgCO2 / 1000
lsoa$van_emissions          = lsoa$van_km     * lsoa$AvgCO2 / 1000
lsoa$company_bike_emissions = lsoa$company_km * lsoa$AvgCO2 / 1000
```

`AvgCO2` is derived entirely from the **car** fleet (`AvgCO2_cars` in `load_car_emissions()`, extended with car ULEV shares). Vans are typically 30–50% more carbon-intensive per km than cars; motorbikes are far less. Van emissions are therefore systematically understated and motorbike emissions overstated, and the manual's *"Van Emissions: as for cars"* ([manual/index.md:334](../PlaceBasedCarbonCalculator.github.io/manual/index.md#L334)) reads as a statement about attribution, not about the emissions factor.

**Fix:** use a van-specific fleet intensity (DfT publishes LGV registrations by CO₂ band), or state the assumption on the chart's Methods tab.

### C2. Road transport is reported as CO₂e but computed from type-approval CO₂

`AvgCO2` comes from the registration/type-approval CO₂ figure per vehicle. The published values are labelled `kgCO₂e` throughout the site. That figure is tailpipe CO₂ only:

- no CH₄/N₂O, so not CO₂e;
- no well-to-tank/upstream fuel emissions, whereas the consumption categories in the same stacked bar *do* include full supply chains (DEFRA consumption accounts);
- type-approval CO₂ is well below real-world CO₂ (NEDC-era figures are typically 20–40% optimistic).

Domestic gas and electricity have the same scope boundary (`R/emissions_factors.R` uses scope-1 gas and location-based scope-2 electricity, no WTT), so the housing and transport parts of the bar are on a narrower basis than the consumption part. Nothing on the site says this.

**Fix:** state the scope boundary in the manual's "How the footprints are calculated" section; consider adding the WTT factors so the stacked bar is on one basis.




### C6. Off-gas heat demand is the *national* median gas-meter consumption

**Where:** [R/other_heating.R:44-47](R/other_heating.R#L44)

```r
gas_average <- dplyr::group_by(domestic_gas, year)
gas_average <- dplyr::summarise(gas_average, median_gas_kwh = median(median_gas_kwh, na.rm = TRUE))
```

Every off-gas household in Great Britain is assumed to use the national-median gas home's kWh. Off-gas homes are disproportionately large, old, rural and less efficient, so this is likely a substantial underestimate, and it removes all local variation in heat demand from the Other Heating layer. The manual's *"typical heating demand and prices are applied"* ([manual/index.md:899](../PlaceBasedCarbonCalculator.github.io/manual/index.md#L899)) does not convey that the demand is a single national number.




### C12. Flight emissions are not reproducible from the published pipeline

**Where:** [R/flights.R:10](R/flights.R#L10), [R/flights.R:25](R/flights.R#L25)

```r
load_flights_od   = function(path = "../../creds2/LDT/data/clean/od_emissions_2021.gpkg")
load_flights_airports = function(path = "../../creds2/LDT/data/clean/airports_clean_second_pass_2021.gpkg")
```

Flights are the single largest transport component of the footprint (GB: 1,092 kgCO₂e/person in 2022, more than car + van + PT combined). The airport-pair emissions come from a pre-built GeoPackage in a different, unpublished repository. The manual states *"Carbon & Place is built in the open, and the analysis behind every map is published"* ([manual/index.md:13](../PlaceBasedCarbonCalculator.github.io/manual/index.md#L13)), and its methods section describes flights only as *"air travel allocated to neighbourhoods via the synthetic population model"* — which describes the downscaling weights, not where the emissions come from.

None of the assumptions actually applied in `get_flights_total_emissions()` appear anywhere on the website:
- international emissions scaled by **0.64** (a fixed 2016 estimate that 34% of passengers are foreign residents, applied to every year 2010–2024);
- international emissions pooled across England/Scotland/Wales and distributed GB-wide, so proximity to an airport genuinely has no effect (the FAQ says this, correctly) but also so that no national variation is preserved;
- Northern Ireland's international flights excluded from the pool;
- domestic emissions split 50:50 between origin and destination nation.

**Fix:** publish the airport-pair build (or a documented data release of it) and add a flights methods section to the manual listing the assumptions above.


### C14. Retrofit map mixes vintages while documenting "latest available"

**Where:** [R/retrofit_lsoa_maps.R:9](R/retrofit_lsoa_maps.R#L9), [:99](R/retrofit_lsoa_maps.R#L99)

The docstring says *"Latest available year is used for each input"* and *"the **2024** house price"*, but the code uses `price_2025`, and `population` is pinned to 2022:

```r
population = population[population$year == 2022,]
sub$percent_EPC = round(sub$epc_total / sub$all_properties * 100)
```

So "% of homes with an EPC" divides a 2026-Q1 EPC count by a 2022 dwelling count, and the docstring's "2024" contradicts both the code and the site's "Average Property Price (2025)".

### D8. Small labelling and cosmetic items

- `data_gas_emissions_household`, `data_elec_emissions_household`, etc. are element IDs on per-**person** values. The column header is correct (`kgCO₂e per person`), so this is not user-visible, but the names are a trap for the next edit.
- [pbcc/ui.js:533](../PlaceBasedCarbonCalculator.github.io/pbcc/ui.js#L533) — `labels: data.labels.filter(d => d.label != 'Goods & Services')` filters a `.label` property off an array of year strings. It happens to be a no-op (every element passes), so the chart is correct by accident.
- The default `src` for every grade image is `/legacy/images/grades/undefined.jpg` — the file exists, so no 404, but the current grade images live at `/images/grades/*.webp`.
- Manual's synthetic-population section ([manual/index.md:462-468](../PlaceBasedCarbonCalculator.github.io/manual/index.md#L462)) lists six characteristics including "Output Area Classification". The IPF is run on five (size, composition, tenure, accommodation type, cars — see `R/synth_pop_seed.R`); OAC enters at the *LCFS matching* step (`make_similarity_table()`), not in building the synthetic population.
- `goods_services_combined_*` includes `housing_other`, which is also shown as its own row in the Overview table and grouped under **Housing** in the simplified overview toggle ([pbcc/ui.js:76-88](../PlaceBasedCarbonCalculator.github.io/pbcc/ui.js#L76)) but under **Other goods & services** in the area report ([reports/la-report.js:227](../PlaceBasedCarbonCalculator.github.io/reports/la-report.js#L227)). The same quantity is filed under two different headings in two places on the same site.
